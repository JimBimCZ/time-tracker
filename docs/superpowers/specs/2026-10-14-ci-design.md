# CI pipeline — design

**Date:** 2026-10-14
**Scope:** one GitHub Actions workflow that gates every PR and every push to `main` on static checks, a build and the e2e smoke suite.

## Goal

Nothing reaches `main` without passing:
- `typecheck`, `lint` and a full build;
- `pnpm e2e`, which covers the real stack: Kong, the 4 services, Postgres, Kafka, Redis and the web app.

## Workflow

Everything lives in one file, `.github/workflows/ci.yml`.

- **Triggers:** `pull_request`, and `push` to `main`. Never `pull_request_target`: the repo is public, and fork PRs must not reach secrets.
- **Permissions:** `contents: read` only.
- **Concurrency:** group `ci-${{ github.ref }}` with `cancel-in-progress: true`. A new push cancels the older run on the same ref.
- **Runner:** `ubuntu-latest`. Docker and Compose are preinstalled. Kong reaches the host services through the existing `extra_hosts: host-gateway` entry.

### Pinned actions

Each action is pinned to the commit SHA of a release at least two weeks old:

| Action | Version | SHA |
|---|---|---|
| `actions/checkout` | v7.0.1 | `3d3c42e5aac5ba805825da76410c181273ba90b1` |
| `pnpm/action-setup` | v6.1.0 | `ea17c68df8912ef543352723c149a84f56e3d413` |
| `actions/setup-node` | v7.0.0 | `820762786026740c76f36085b0efc47a31fe5020` |

`pnpm/action-setup` has no `version` input: it reads `pnpm@12.8.1` from `packageManager` in `package.json`. It runs with `cache: true`, which caches the pnpm store keyed on `pnpm-lock.yaml`. `setup-node` uses Node `24.20.0`, the same version as the Dockerfiles.

### Job `checks` (timeout 10 min)

1. Checkout, pnpm, Node.
2. `pnpm install --frozen-lockfile`
3. `pnpm typecheck`
4. `pnpm lint`
5. `pnpm -r build`

### Job `e2e` (timeout 15 min)

This job runs in parallel with `checks`.

1. Checkout, pnpm, Node.
2. `pnpm install --frozen-lockfile`
3. `for s in services/*; do cp $s/.env.example $s/.env; done`
4. `pnpm --filter @tt/e2e exec playwright install --with-deps chromium`
5. `pnpm e2e`. GitHub sets `CI=true`, so the config switches to `forbidOnly`, the `github` reporter, and `reuseExistingServer: false`.
6. Only if the job failed: `docker compose logs --no-color`.

## Docs

Add one line to the Commands section of `CLAUDE.md`: CI runs `typecheck`, `lint`, `build` and `e2e` on every PR and every push to `main`.

## Manual follow-up (repo owner)

After the merge, protect `main` so that the `checks` and `e2e` status checks must pass. CI does not change repository settings.

## Out of scope

- Docker image builds: they come with the Kubernetes step.
- Contracts backward-compatibility check: there are no event schemas yet.
- Playwright report artifact: the `github` reporter writes no HTML report, and tracing is off.
- Caching the Playwright browser download.
